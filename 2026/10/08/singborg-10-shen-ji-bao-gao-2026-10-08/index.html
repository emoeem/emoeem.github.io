4.2 高危项（已单独提示，均带回滚）

  • 第 5、6 项（secret 轮换）：唯一会影响外部脚本的改动。如果你的其它设备/脚本里硬编码了旧的 clash secret，轮换后它们会 401。已确认本机面板（127.0.0.1:9096）是按文件 mtime 动态读取密钥的，轮换对它透明；zashboard 入口用 #/setup?…&secret= 深链自动带密钥，无需手输。
  • 统一回滚一行（脚本每次运行都会打印，并把当次备份路径填进去）：
    sudo install -m 600 -o root -g root /etc/sing-box/config.json.bak.<时间戳> /etc/sing-box/config.json && sudo systemctl restart sing-box
  • 脚本对第 5~10 项任一步失败都会自动用当次备份回滚并重启服务（30 秒等待），且会打印同样的手动命令。

五、第 4 步 · 上线流程（先备份 → check → 才生效；失败 10 秒内回滚）

脚本：/home/emo/Documents/deepseek-harness/default-workspace/apply-hardening-2026-10-08.sh（320 行，bash -n 通过，755）

执行顺序：

  1. 前置备份：install -m600 生成 /etc/sing-box/config.json.bak.<TS>，另存一份原配置到临时文件用于失败对照
  2. 备份加固 + 归档（清单 1、2）
  3. 用 python 改写候选配置（清单 5、6、9、10）：轮换两个 secret、收紧 CORS/移除 allow_private_network、删除 block 出站、Download.default + Auto/Auto-Japan 剔除下载节点；仅改这些字段，其余字节不动 → 得到最小 diff
  4. 先停服再 sing-box check：避免与正在运行的 eBPF 争用 BPF 资源导致误报；check 失败则按原配置立即 start 并退出（不动线上配置）
  5. 原子替换：install + mv 到 /etc/sing-box/config.json（0600 root）
  6. 写 drop-in + systemctl daemon-reload（清单 4）
  7. 启动 + 全套健康检查：服务 active（30s）→ 端口 7892/9090/9091 → 启动后 journalctl ERROR 计数 → 新密钥 200 / 旧密钥非 200 / 无密钥 401 → CORS 面板源放行且 evil.example 不放行 → 9096 面板 200 → 面板 /api/state 能读到新密钥 → 经 7892 代理 gstatic/generate_204 = 204；任一失败即回滚
  8. 汇总：备份路径、打码 diff、一行回滚命令、新密钥前 6 字符与长度

5.1 实际执行结果（2026-10-08）

第一次执行（13:35:51）——误报回滚，正式配置未落盘。

  • 现象：sing-box check 通过 → 原子替换成功 → 健康检查报「端口未监听: 7892 9090 9091」→ 自动回滚，服务恢复。
  • 排查证据：① systemd 日志显示新实例是 Stopping → Deactivated successfully（被脚本主动停），不是崩溃——没有 Main process exited / Failed with result；② 新实例存活 586ms / 538ms、各耗 CPU 538ms，说明它正在正常启动过程中就被判失败；③ 同期测试脚本 T1.3 也报端口缺失，但几秒后 T2/T3 全部连通。
  • 根因（脚本 bug，非配置问题）：unit 为 Type=simple，systemctl is-active 在进程 fork 后立即返回 active，而健康检查零等待就查端口；sing-box 加载 17 个 rule-set + eBPF 程序需要数秒。
  • 修复：端口检查改为最长 60 秒轮询（进程若自行退出则立即判失败），真失败时先打印新实例最后 40 行日志再回滚。

第二次执行（13:45:03 生效）——成功。

  • 流程：sing-box check 通过 → 原子替换（16641 B, mode 600）→ 启动 → 全套健康检查通过 → 未触发回滚。
  • 独立复核（emo 权限，13:53 实测）：systemd active，MainPID 168960；Wants=network-online.target 已进事务；7892/9090/9091/9096 全部 LISTEN；outbounds 由 22 → 21（block 出站已移除）；CORS 对 https://evil.example 不再返回 Access-Control-Allow-Origin，对 http://127.0.0.1:9096 / http://localhost:9096 分别回显该源；无密钥访问 9090 → 401；经 7892 代理 gstatic → 204（0.33s）；出口 IP ；新配置启动后 journalctl 无新增 ERROR（最近一条 ERROR 为 13:34:32，属切换前的旧配置）。

6.2 关于「Akamai 回声是国内 IP」的说明（重要，避免误判为泄漏）

whoami.akamai.net 的回声是 （AS4134 中国电信四川），但这是直连解析分流造成的：该名字命中 must-direct / dns-direct 规则，由国内递归解析器解析，Akamai 权威侧看到的是国内递归地址。CDN/国内域名走直连解析是常见且正确的设计，不是 DNS 泄漏。真正的泄漏判据是 T5.1 的 Google ECS 回声是否落在国内网段——实测落在 Cloudflare，判定通过。

6.5 测试方法自身的两次修正（都不是 sing-box 的问题，如实记录）

  1. 零等待误判端口：见 5.1，已改为 60 秒轮询，并在测试脚本开头同样加了等待，修掉 T1.3 的误报。
  2. www.qq.com 反爬导致的假失败：第一次运行时 T2.2 → 501、T6 出现 138 次「失败」，全部来自同一个 URL——腾讯边缘（Server: stgw）对 curl 默认 UA 直接返回 501，带浏览器 UA 即 200；同批次的 baidu 直连 200、代理路径全部 200。已改为 jd.com 并统一带浏览器 UA。另外把 T6 CPU 计数改成小数秒（原来 120 秒只显示「0s」），T7 的 nft 规则补上 IPv6 分支（本机默认走 IPv6 直连，原规则只写 ip daddr 拦不住），urltest 等待上限 360→480 秒（其检测周期为 5 分钟）。

七、第 6 步 · 回滚步骤与维护建议

7.1 回滚（三层，任选）

  1. 配置回滚（最常用）：
    sudo install -m 600 -o root -g root /etc/sing-box/config.json.bak.<时间戳> /etc/sing-box/config.json
sudo systemctl restart sing-box
systemctl is-active sing-box && ss -ltn | grep -E '7892|9090|9091'
  2. drop-in 回滚（只撤开机等待网络）：sudo rm /etc/systemd/system/sing-box.service.d/20-network-online.conf && sudo systemctl daemon-reload
  3. 备份权限回滚（一般不需要）：sudo chmod 755 /etc/sing-box/backups; sudo find /etc/sing-box -maxdepth 1 -name 'config.json.bak.*' -exec chmod 644 {} +

7.2 维护建议

  1. 每季度跑一次本审计的两个脚本（先 –dry-run 看 diff）；sing-box 有新版时先在 --dry-run 下核对 deprecated 列表。
  2. 统一脚本来源：只从 /home/emo/pkgbuild-source 运行同步脚本，删除或同步 Singborg 里的旧副本，消除 S1 漂移。
  3. 备份保留：保留「最新 10 份 + 7 天内不归档」，归档文件另存到加密盘更稳妥；备份里含明文凭据，务必保持 600。
  4. 密钥轮换：本次轮换后，建议每 6 个月轮换一次；轮换只需改配置并重启，面板自动跟上。
  5. 待你确认的新项：chmod 600 /var/lib/sing-box/cache.db（当前 644，本地可读 DNS 查询历史）。这不在已授权的 14 项内，你点头我再加进脚本。
  6. 节点口令复用（第 7 项）属服务商侧，建议在服务商面板逐节点改独立口令。
  7. 监控：journalctl -u sing-box -p warning --since today 每周扫一遍；missing default interface 应在 drop-in 生效后不再出现。
  8. 不要把 experimental.clash_api.secret 写回任何会进 git 的文件；generate-sanitized-config.py 修好后再用它生成公开快照。
