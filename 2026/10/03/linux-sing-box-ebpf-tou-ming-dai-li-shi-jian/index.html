Linux 上的 sing-box + eBPF 透明代理实践

这不是只有最终配置的一篇教程，而是 Singborg 整套实验记录的总览：从 daed 时代的 DNS 故障开始，到 sing-box 网络审计、功能验收、eBPF 预检与 A/B 试跑，再到面板、安全配置管线、规则集维护、脚本化运维和最终收尾。

最终状态

截至 2026-10-02：

  • eBPF local.cgroup 接管本机流量
  • shared.packet_rewrite / TCX 接管 virbr0 上的共享流量
  • 国内域名/IP 直连，海外流量进入 Proxy → Auto
  • DNS 53 端口全部劫持
  • 海外 DNS 使用代理侧 DoH，国内 DNS 使用阿里 / 腾讯 DoH
  • DNS 广告拦截使用 predefined + NXDOMAIN
  • 连接层继续使用规则集拦截，覆盖浏览器自带 DoH 等绕过 DNS 劫持的情况
  • 15 份规则集，其中 6 份来自自建 sing-box-rule-sets
  • 自研 sing-box-panel 提供订阅、节点、分应用策略和安全配置
  • 配置变更统一走 check → 备份 → 原子替换 → 重启 → 健康检查 → 失败回滚

eBPF 的关键结论

预检 51 项全过，不代表数据面就一定能用。

实际 A/B 试跑才发现：

  • local 的 TC 数据面受当前内核能力限制，不能用
  • shared 的 TCX / packet_rewrite 路径实际可以工作
  • VM / bridge 流量和本机进程的覆盖范围不同
  • rootless Podman 的 pasta 用户态转发不属于 shared bridge 覆盖路径
  • 因此不能简单写成“eBPF 能接管所有容器”，需要按网络路径分别验证

这也是为什么项目保留了独立的 eBPF A/B 试跑套件。

DNS 与广告拦截

DNS 是这套配置最容易出现“看起来正常、实际绕过”的地方。

当前策略是：

53 端口
  ↓
sing-box hijack-dns
  ├─ 国内 → 阿里 / 腾讯 DoH
  └─ 海外 → 代理侧 Cloudflare / Google DoH

广告域名
  ├─ DNS 层 → predefined + NXDOMAIN
  └─ 连接层 → 规则集兜底

之所以不用单纯的 reject，是因为 REFUSED 在当前客户端路径上可能导致解析重试；NXDOMAIN 是正常的“域名不存在”响应，失败速度更快。

规则集与配置

当前配置包含 15 份规则集，来源包括官方 sing-geosite / sing-geoip 数据和自建规则包：

  • anti-AD
  • geoip/cn-fresh
  • cncidr-mihomo
  • must-direct
  • ads-extra
  • adblockfilters
  • geosite/category-ads-all
  • geosite/cn
  • geosite/geolocation-!cn
  • geosite/google
  • geosite/category-ai-!cn
  • geoip/cn
  • geosite/apple@cn
  • Ads_AWAvenue
  • geoip/telegram

完整字段结构、DNS 设计、规则顺序和脱敏配置见 配置与规则集文档。

面板与安全配置管线

sing-box-panel 负责订阅、节点、分应用策略等日常操作，但它不是直接“写完 JSON 就重启”。

配置修改统一经过：

check
  ↓
备份当前配置
  ↓
原子替换
  ↓
restart
  ↓
健康检查
  ↓
失败 → 回滚

具体操作见 面板指南。
