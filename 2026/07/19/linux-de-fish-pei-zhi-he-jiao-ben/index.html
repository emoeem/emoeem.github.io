Fish + fzf + FFmpeg 工具套件使用与优化说明

文档日期：2026-07-19
适用环境：CachyOS / Arch Linux、Fish Shell、支持 ANSI 真彩色的终端
升级包位置：/tmp/fzf-suite-v2
正式安装位置：~/.local/bin 与 ~/.config/fish

1. 文档说明

这套工具把文件搜索、目录跳转、编辑器打开、Git 操作、历史命令、媒体预览和常见 FFmpeg 操作统一到了 fzf 界面中。

本次优化主要解决以下问题：

  1. 图片或视频封面在终端中反复预览后发生堆叠、残影或覆盖。
  2. 原来的水印脚本偏向视频，不能方便地给普通照片添加文字或 Logo 水印。
  3. 不同脚本的文件选择器、预览窗口和快捷键不一致。
  4. fzf-cd 只能输出目录，无法可靠地改变当前 Fish 的工作目录。
  5. Fish 的历史搜索存在选中后直接执行的风险。
  6. Fish 启动配置中交互工具、环境变量、快捷键和缩写较为分散。
  7. 媒体工具缺少统一入口、图片预览、音频封面预览和批量操作能力。

升级后的设计原则是：

  • 预览只输出稳定的 ANSI 字符，不发送 Kitty、iTerm2 或 sixel 图形协议。
  • 所有主要选择器都使用统一的 fzf-preview 预览入口。
  • 图片、视频、音频、文本和目录使用同一个预览系统。
  • Fish 中的历史搜索只把命令插入命令行，留给用户检查后再执行。
  • 媒体脚本既能无参数交互使用，也尽量支持直接传入文件。
  • 安装前先完整备份，部署后自动执行语法检查。

2. 当前部署状态

升级后的文件已经暂存在：

/tmp/fzf-suite-v2/
├── bin/
├── fish/
├── atuin/
└── install.sh

截至本文档生成时，升级包尚未写入正式的用户配置目录。当前 ~/.local/bin 和 ~/.config/fish 仍然是部署前版本。

原因不是脚本语法或测试失败，而是自动写入用户目录的部署通道未能完成。因此需要在自己的终端中运行一次安装器。

3. 安装与重新加载

3.1 执行安装

在终端中运行：

/tmp/fzf-suite-v2/install.sh

安装器会执行以下操作：

  1. 创建带时间戳的备份目录。
  2. 备份整个 ~/.local/bin。
  3. 备份整个 ~/.config/fish。
  4. 将新脚本安装到 ~/.local/bin。
  5. 更新 Fish 主配置、函数和命令补全。
  6. 对所有已安装的 Bash 和 Fish 脚本执行语法检查。
  7. 输出实际备份目录。

成功后会看到类似：

部署完成。
备份目录: /home/emo/.local/state/fzf-suite/backups/20260719-123456
运行 exec fish 重新加载配置。

3.2 重新加载 Fish

安装完成后运行：

exec fish

exec fish 会用新的 Fish 进程替换当前 Shell，使环境变量、缩写、函数、补全和快捷键立即生效。

也可以关闭当前终端，再打开一个新终端。

3.3 确认命令来源

部署后检查：

type -a fzf-fftools
type -a fzf-preview
type -a fzf-add-watermark
type -a fzf-media
type -a fzf-cd

主要命令应指向：

/home/emo/.local/bin/<命令名>

检查关键文件：

ls -l ~/.local/bin/fzf-preview
ls -l ~/.local/bin/fzf-add-watermark
ls -l ~/.config/fish/config.fish
ls -l ~/.config/fish/functions/fish_user_key_bindings.fish

4. 备份与回滚

4.1 备份目录

每次执行安装器都会创建新的备份：

~/.local/state/fzf-suite/backups/<时间戳>/
├── local-bin/
└── fish/

查看已有备份：

ls -lt ~/.local/state/fzf-suite/backups

4.2 查看某次备份

set backup ~/.local/state/fzf-suite/backups/20260719-123456
ls "$backup/local-bin"
ls "$backup/fish"

把示例时间戳替换为安装器实际输出的目录。

4.3 完整回滚

建议先退出所有其他 Fish 终端，再执行：

backup="$HOME/.local/state/fzf-suite/backups/20260719-123456"
stamp="$(date +%Y%m%d-%H%M%S)"

mv "$HOME/.local/bin" "$HOME/.local/bin.after-fzf-upgrade-$stamp"
mv "$HOME/.config/fish" "$HOME/.config/fish.after-fzf-upgrade-$stamp"

cp -a "$backup/local-bin" "$HOME/.local/bin"
cp -a "$backup/fish" "$HOME/.config/fish"

exec fish

这种方式不会直接删除升级后的目录，而是先把它们改名保留。如果需要比较新旧版本，可以使用：

diff -ru "$HOME/.local/bin.after-fzf-upgrade-<时间戳>" "$HOME/.local/bin"
diff -ru "$HOME/.config/fish.after-fzf-upgrade-<时间戳>" "$HOME/.config/fish"

配置会按命令是否存在，自动添加缩写：

5.4 Arch/AUR 包管理

fzf-pkg 使用：

  • pacman 管理官方仓库包。
  • yay 搜索和安装 AUR 包。
  • omarchy-sudo-keepalive 保持 sudo 会话。
  • omarchy-show-done 显示完成通知。

如果系统没有 Omarchy 辅助脚本，fzf-pkg 的官方包/AUR 安装流程需要相应调整；卸载流程主要依赖 pacman 和 yay。

7. fzf 通用操作

大多数选择界面支持：

按键 功能
↑ / ↓ 移动选择
输入文字 模糊筛选
Enter 确认
Esc 取消
Tab 选择或取消当前项，多选界面可选择多项
Shift-Tab 反向选择并向上移动
Ctrl-A 在支持的界面中全选
Ctrl-D 在支持的界面中取消全选
Ctrl-Up / Ctrl-Down 上下滚动预览
Alt-Up / Alt-Down 上下滚动预览
Alt-D / Alt-U 预览向下/向上滚动半页
Alt-P 显示或隐藏预览窗口
Alt-W 切换预览窗口自动换行

默认预览窗口使用：

right:60%:nowrap:border-left

也就是：

  • 预览位于右侧。
  • 大约占终端宽度的 60%。
  • 默认不自动换行。
  • 左侧有分隔线。
  • 需要查看超长文本时按 Alt-W 临时开启换行。

8. Fish 快捷键

8.1 快捷键总表

快捷键 功能 执行结果
Ctrl-T 搜索文件 把一个或多个文件路径插入当前命令行
Ctrl-R 搜索当前 Fish 历史 把选择的命令插入命令行，不自动执行
Alt-C 搜索目录 进入选择的目录
Alt-E 搜索并编辑文件 用 $VISUAL 或 $EDITOR 打开一个或多个文件
Alt-V 媒体浏览器 预览并打开图片、视频或音频
Alt-G Git 面板 打开分支、提交、变更、差异和 Stash 菜单
Alt-R Atuin 全局历史 把 Atuin 中选择的命令放入当前命令行
Alt-P 切换预览 在 fzf 界面中显示或隐藏预览
Alt-W 切换换行 在 fzf 界面中切换预览换行

8.2 Ctrl-T：插入文件

先输入命令的一部分：

ffprobe

按 Ctrl-T，搜索文件，按 Enter 后路径会插入当前命令行：

ffprobe 'video/demo.mp4'

多选时使用 Tab。

8.3 Ctrl-R：Fish 历史

Ctrl-R 使用 fzf --fish 提供的历史搜索。升级后取消了选中历史后立即执行的自定义逻辑。

正确流程是：

  1. 按 Ctrl-R。
  2. 搜索历史。
  3. 按 Enter。
  4. 命令出现在当前命令行。
  5. 检查或修改。
  6. 再按一次 Enter 执行。

这可以避免误选 rm、sudo、包管理或 Git 命令后直接运行。

8.4 Alt-R：Atuin 全局历史

Alt-R 会读取最多 5000 条 Atuin 历史记录，并按当前命令行内容作为初始查询。

与直接启动 Atuin TUI 不同，这个绑定经过 fzf 选择后只替换当前命令行，不会自动执行。

也可以直接运行：

fzf-history
fzf-history git
fzf-history ffmpeg

直接运行时，它把选择结果输出到标准输出，适合脚本组合。

8.5 Alt-C 与 fzf-cd

在 Fish 中：

fzf-cd
fzf-cd ~/code

Fish 函数会调用同名外部程序取得目录，再执行真正的 builtin cd，因此当前 Shell 的目录会发生变化。

外部脚本本身只输出路径。这是因为子进程无法直接修改父 Shell 的工作目录。Fish 函数解决了这个边界问题。

8.6 Alt 快捷键无响应

部分终端或桌面环境会抢占 Alt 组合键。如果 Alt-E、Alt-V、Alt-G 或 Alt-R 没有反应：

fish_key_reader

然后按目标组合键，查看终端实际发送的序列。

也可以使用 Esc 前缀测试，例如先按 Esc，再按 v，通常等价于 Alt-V。

9. 统一预览系统

9.1 预览入口

通用入口：

fzf-preview <路径>

兼容旧脚本的媒体入口：

fzf-preview-video <路径>

目前 fzf-preview 会转交给升级后的 fzf-preview-video，所以两者具有同样的文件类型识别能力。

手动测试：

FZF_PREVIEW_COLUMNS=100 FZF_PREVIEW_LINES=36 fzf-preview photo.jpg
FZF_PREVIEW_COLUMNS=100 FZF_PREVIEW_LINES=36 fzf-preview movie.mp4
FZF_PREVIEW_COLUMNS=100 FZF_PREVIEW_LINES=36 fzf-preview music.flac
FZF_PREVIEW_COLUMNS=100 FZF_PREVIEW_LINES=36 fzf-preview README.md
FZF_PREVIEW_COLUMNS=100 FZF_PREVIEW_LINES=36 fzf-preview .

9.2 不同文件的预览方式

文件类型 预览内容
目录 目录名和两层目录树，最多约 200 行
文本 文件信息和前 300 行语法高亮
JSON/XML/Shell 按文本方式预览
图片 ANSI 字符图片、格式、尺寸、色彩空间
视频 缓存的视频帧、编码、分辨率、时长、码率
音频 内嵌封面；没有封面时生成波形图
未知文件 MIME、大小、修改时间；能识别扩展名时尝试媒体预览

9.3 图片堆叠问题是怎样修复的

旧式终端图片预览工具可能使用以下协议直接在终端画布上放置位图：

  • Kitty graphics protocol
  • iTerm2 inline images
  • sixel

这些图像不完全属于普通文本缓冲区。fzf 切换选中项或清理预览窗口时，只能可靠清理普通字符，图形层可能继续留在终端画布上，于是出现：

  • 查看多个图片后封面叠在一起。
  • 新图片覆盖旧图片的一部分。
  • 退出 fzf 后图片仍留在屏幕上。
  • 预览区缩放后图像跑到列表区。

升级后的核心处理是：

chafa --format symbols

--format symbols 强制 Chafa 输出 ANSI 彩色字符块，不使用终端位图协议。因此：

  • 图片成为普通终端文字输出。
  • fzf 能在刷新预览时完整覆盖旧内容。
  • 退出 fzf 后不会留下独立图形层。
  • Kitty、Foot、WezTerm、Alacritty 等终端的表现更一致。
  • SSH、tmux 和普通 TTY 环境中的兼容性更好。

预览还会主动限制尺寸：

  • 最宽 120 列。
  • 最窄 24 列。
  • 图片区域最高约 34 行。
  • 自动根据 FZF_PREVIEW_COLUMNS 和 FZF_PREVIEW_LINES 调整。

9.4 为什么默认 nowrap

图片字符和媒体信息如果被终端二次换行，预览高度会突然改变，容易产生滚动错位或残留。

因此所有主要媒体选择器默认：

nowrap

查看长文本、Git diff 或进程命令行时，可以按 Alt-W 开启换行。

9.5 视频缩略图缓存

缓存目录：

~/.cache/fzf-media-preview

缓存键由以下信息共同计算：

  • 文件的绝对路径。
  • 文件大小。
  • 文件修改时间。

因此：

  • 同一个未修改的视频不需要反复抽帧。
  • 文件内容更新后会生成新的缓存。
  • 不同目录中的同名文件不会互相覆盖。

缩略图生成顺序：

  1. 优先使用 ffmpegthumbnailer。
  2. 失败时使用 ffprobe 获取时长。
  3. 从视频大约 10% 的位置抽帧，最长不超过 60 秒位置。
  4. 极短视频从开头抽帧。

清理缓存：

rm -rf ~/.cache/fzf-media-preview

下次预览会自动重新生成。

9.6 音频预览

音频预览优先提取第一路内嵌视频流作为封面：

MP3/FLAC/M4A 内嵌专辑封面

如果没有封面，会生成单声道波形图，再由 Chafa 转为 ANSI 字符。

这使 fzf-media 不仅能浏览视频和照片，也能按专辑封面或波形辨认音频文件。

10. fzf-media 媒体浏览器

10.1 基本使用

在当前目录递归搜索支持的媒体：

fzf-media

传入指定文件：

fzf-media photo.jpg movie.mp4 song.flac

界面操作：

按键 功能
Enter 使用桌面默认程序打开选中的文件
Ctrl-Y 把选中的路径复制到 Wayland 剪贴板
Tab 多选
Alt-P 切换预览
Alt-W 切换换行

10.2 只输出路径

fzf-media --print

这时不会打开文件，只输出选择的路径，适合命令组合：

set media (fzf-media --print)
printf '%s\n' $media

也可以：

mpv (fzf-media --print)

10.3 支持的扩展名

视频：

mp4 mkv mov avi webm ts m4v flv mpeg mpg wmv 3gp

音频：

mp3 flac wav aac m4a opus ogg wma ac3 aiff ape

图片：

jpg jpeg png webp bmp gif tiff tif avif heic heif jxl apng

11. fzf-ed 文件编辑器

交互搜索文件：

fzf-ed

直接打开指定文件：

fzf-ed README.md
fzf-ed src/main.rs src/lib.rs

编辑器优先级：

  1. $VISUAL
  2. $EDITOR
  3. nvim

选择界面支持：

  • Tab 多选。
  • Ctrl-A 全选。
  • Ctrl-D 取消全选。
  • Alt-P 切换预览。
  • Alt-W 切换预览换行。

默认递归排除：

.git node_modules .cache target build dist

12. fzf-kill 进程管理

12.1 安全终止

fzf-kill

默认只显示当前用户的进程，并按 CPU 使用率排序。右侧显示：

  • PID 和 PPID。
  • 用户。
  • CPU 和内存占用。
  • 运行时长。
  • 启动时间。
  • 完整命令。
  • 进程树。

选中后不会立即终止，而是先显示 PID 并要求确认：

将向以下 PID 发送 TERM: 1234 5678
确认？[y/N]

12.2 强制终止

fzf-kill --kill

这会发送 KILL。只应在普通 TERM 无法让进程正常退出时使用。

12.3 自定义信号

fzf-kill --signal HUP
fzf-kill --signal INT
fzf-kill --signal STOP
fzf-kill --signal CONT

推荐顺序：

  1. 首先使用默认 TERM。
  2. 需要模拟中断时使用 INT。
  3. 需要重新加载配置时使用应用支持的 HUP。
  4. 最后才使用 KILL。

13. fzf-git Git 面板

必须在 Git 仓库内运行：

fzf-git

13.1 分支

fzf-git branch

files status

16. fzf-add-watermark 水印工具

这是本次功能升级最明显的脚本之一。它现在不仅支持视频，也支持普通照片、透明 PNG、WebP、AVIF 和多种动态媒体。

16.1 最简单的交互使用

fzf-add-watermark

脚本会依次询问：

  1. 输入图片或视频。
  2. 文字水印还是图片水印。
  3. 水印位置。
  4. 边距。
  5. 不透明度。
  6. 文字、颜色、样式或 Logo 文件。
  7. 输出文件。
  8. 是否执行。

完成后直接在终端中预览结果。

16.2 完整参数

fzf-add-watermark [选项] [输入文件]
参数 说明 默认值
--text TEXT 使用文字水印 交互选择
--logo FILE 使用图片 Logo 水印 交互选择
--position POS 九宫格位置 bottom-right，仅 -y 模式自动使用
--margin PX 距画面边缘像素 24
--opacity 0..1 水印不透明度 0.85
--font-size PX 文字字号 画面高度约 4%，限制在 18 到 96
--font-color COLOR FFmpeg 颜色名或十六进制颜色 white
--font FILE 指定字体文件 自动查找 Noto Sans CJK SC
--style STYLE 文字样式 border
--scale PERCENT Logo 宽度占画面宽度的百分比 15
-o FILE 输出路径 原文件名加 _watermarked
--output FILE 与 -o 相同 原文件名加 _watermarked
-y / --yes 使用默认值并跳过执行确认 关闭
--no-preview 完成后不显示终端预览 关闭
-h / --help 显示帮助 -

16.3 九宫格位置

可用位置：

top-left       top-center       top-right
center-left    center           center-right
bottom-left    bottom-center    bottom-right

示意：

+-------------------------------+
| top-left   top-center top-right|
|                               |
| center-left  center center-right
|                               |
| bottom-left bottom-center     |
|                  bottom-right |
+-------------------------------+

16.4 文字样式

样式 效果
none 只有文字，不加背景、阴影或描边
box 文字后方添加半透明黑色底框
shadow 添加黑色偏移阴影
border 添加黑色描边，默认选项

一般建议：

  • 明暗复杂的照片使用 border。
  • 文档截图或内部资料使用 box。
  • 画面较干净时可使用 shadow。
  • 已经为文字留出纯色区域时可使用 none。

16.5 给照片添加文字水印

fzf-add-watermark --text '旅行 2026' photo.jpg

右下角水印并直接执行：

fzf-add-watermark \
  -y \
  --text '旅行 2026' \
  --position bottom-right \
  --opacity 0.75 \
  photo.jpg

指定字号、颜色和样式：

fzf-add-watermark \
  --text '版权所有' \
  --font-size 42 \
  --font-color '#FFD700' \
  --style shadow \
  --position bottom-center \
  photo.png

指定输出文件：

fzf-add-watermark \
  -y \
  --text '内部资料' \
  --position bottom-right \
  --opacity 0.65 \
  -o output.jpg \
  input.jpg

16.6 给照片添加 Logo

推荐使用带透明通道的 PNG Logo：

fzf-add-watermark \
  --logo logo.png \
  --scale 18 \
  --position top-right \
  photo.jpg

降低 Logo 不透明度：

fzf-add-watermark \
  -y \
  --logo logo.png \
  --scale 12 \
  --opacity 0.55 \
  --margin 32 \
  --position bottom-left \
  -o branded.webp \
  photo.webp

--scale 12 表示 Logo 的目标宽度约为原图宽度的 12%，不是把 Logo 缩放到自身尺寸的 12%。

16.7 给视频添加水印

文字水印：

fzf-add-watermark \
  --text '@example' \
  --position top-left \
  --opacity 0.8 \
  video.mp4

Logo 水印：

fzf-add-watermark \
  --logo logo.png \
  --scale 18 \
  --position bottom-right \
  video.mp4

批处理脚本中使用：

for file in *.jpg; do
  fzf-add-watermark \
    -y \
    --text 'Copyright 2026' \
    --position bottom-right \
    --opacity 0.7 \
    --no-preview \
    "$file"
done

16.8 输出规则

默认输出：

photo.jpg  -> photo_watermarked.jpg
video.mp4  -> video_watermarked.mp4

对于 HEIC、HEIF 和 JXL 静态图片，默认输出改为 PNG：

photo.heic -> photo_watermarked.png

输出文件不能与输入文件相同，以避免直接破坏原文件。

静态图片编码：

输出格式 编码行为
JPEG 高质量 JPEG，-q:v 2
PNG PNG 编码
WebP libwebp，质量 92
AVIF libaom-av1 静态图片模式

视频编码：

输出格式 编码行为
MP4/MOV/M4V 等 H.264，CRF 20，音频复制
WebM VP9，音频复制
GIF 无音频，循环播放
APNG APNG 编码，无音频

MP4、MOV 和 M4V 会增加 faststart，便于网页或网络环境快速开始播放。

16.9 中文字体

脚本会尝试：

fc-match 'Noto Sans CJK SC'

如果中文显示成方框，手动指定字体：

fzf-add-watermark \
  --text '中文水印' \
  --font /usr/share/fonts/noto-cjk/NotoSansCJK-Regular.ttc \
  photo.jpg

查找字体：

fc-match -f '%{file}\n' 'Noto Sans CJK SC'
fc-list :lang=zh family file | head

17. 其他媒体命令

17.1 fzf-burn-subs

把 SRT、ASS、VTT 或 SSA 字幕烧录进视频画面：

fzf-burn-subs

直接传入视频和字幕：

fzf-burn-subs video.mkv subtitles.ass

默认输出：

video_subbed.mp4

字幕烧录会重新编码视频为 H.264，音频直接复制。

注意：烧录后的字幕已经成为画面的一部分，不能像软字幕一样关闭。

17.2 fzf-compress-video

fzf-compress-video
fzf-compress-video video.mp4

可选 CRF：

CRF 说明
18 接近无损，文件较大
23 推荐，高质量
28 中等压缩
32 高压缩，文件较小

可选分辨率：

保持原始
1080p
720p
480p

默认输出：

video_compressed.mp4

视频使用 H.264 medium，音频使用 AAC 128 kbps。

17.3 fzf-concat-video

交互选择至少两个视频：

fzf-concat-video

直接指定顺序：

fzf-concat-video part1.mp4 part2.mp4 part3.mp4

默认输出：

concat_output.mp4

该工具使用 -c copy 无损拼接，因此输入片段应具有兼容的：

  • 视频编码。
  • 音频编码。
  • 分辨率。
  • 帧率和时间基。
  • 流布局。

如果片段参数不一致，应先用 fzf-convert-media 或 fzf-ffmpeg-batch 统一转码。

17.4 fzf-convert-media

交互使用：

fzf-convert-media

直接指定输入和目标键：

fzf-convert-media input.mkv mp4-hevc
fzf-convert-media input.wav opus-128
fzf-convert-media input.png webp-80

视频目标：

mp4 mkv mp4-hevc mkv-hevc webm-vp9 webm-vp8
mov m4v avi flv ts wmv 3gp gif

音频目标：

mp3-320 mp3-192 mp3-128
m4a-256 m4a-192 m4a-128
aac opus-128 opus-64
flac alac wav ogg ac3

图片目标：

jpg-90 jpg-75 jpg-50
png webp-ll webp-80
tiff bmp avif

交互模式会先调用 fzf-validate-media 验证文件，再根据视频、音频或图片类型显示相应的目标格式。

17.5 fzf-extract-audio

fzf-extract-audio
fzf-extract-audio video.mp4

输出格式：

格式 编码
M4A AAC 192 kbps
MP3 MP3 192 kbps
Opus Opus 128 kbps
WAV PCM 16 bit
OGG Vorbis 192 kbps

17.6 fzf-merge-av

用于合并下载后分离的视频流和音频流：

fzf-merge-av
fzf-merge-av ~/Downloads/media

脚本按文件名识别以下标记：

.video_only / .audio_only
.video      / .audio
.vi         / .au
_video_only / _audio_only
_video      / _audio

示例：

episode01.video_only.mp4
episode01.audio_only.m4a

输出：

episode01.mp4

脚本会：

  1. 扫描当前目录。
  2. 按标准化后的文件名配对。
  3. 用 ffprobe 验证视频流和音频流。
  4. 跳过已经存在的输出。
  5. 默认全选待处理项目。
  6. 使用 -c copy 合并，不重新编码。
  7. 最后报告成功、跳过和失败数量。

17.7 fzf-mute-video

fzf-mute-video
fzf-mute-video a.mp4 b.mkv

交互模式默认全选当前目录中的视频。脚本使用流复制并移除音轨：

video.mp4 -> video_muted.mp4

因为不重新编码视频，所以处理速度通常很快。

17.8 fzf-speed-video

fzf-speed-video
fzf-speed-video video.mp4

可选速度：

0.5x 0.75x 1.25x 1.5x 2.0x 3.0x

输出：

video_x1.5.mp4

视频通过 setpts 改变速度，音频通过 atempo 处理。

当前版本对音频 atempo 使用单级 0.5 到 2.0 范围。选择 3.0x 时，视频会按 3 倍速处理，但音频滤镜被限制到 2 倍，可能产生不同步。需要可靠的 3 倍速音频时，应使用链式滤镜：

atempo=1.5,atempo=2.0

17.9 fzf-trim-video

fzf-trim-video
fzf-trim-video video.mp4

时间可写为：

00:01:30
90

持续时长留空表示裁剪到结尾。

默认输出：

video_clip.mp4

脚本使用 -c copy 进行关键帧裁剪，速度快且不损失画质，但开始位置可能落在最接近的关键帧，不保证逐帧精确。

需要逐帧精确裁剪时必须重新编码。

17.10 fzf-validate-media

验证指定文件：

fzf-validate-media video.mp4 photo.jpg audio.flac

交互批量验证：

fzf-validate-media

结果示例：

有效: 3  无效: 1

它使用 ffprobe 检查文件是否包含可识别的媒体流。它适合发现：

  • 下载不完整。
  • 扩展名与内容不匹配。
  • FFmpeg 无法识别。
  • 文件为空或损坏严重。

它不是完整的逐帧解码检测。需要更严格检查时可以使用：

ffmpeg -v error -i input.mp4 -f null -

17.11 fzf-video-to-gif

fzf-video-to-gif
fzf-video-to-gif video.mp4

可设置：

  • 开始时间。
  • 持续秒数。
  • 原始、480 或 360 像素宽度。
  • 10、15 或 24 fps。

脚本使用两遍流程：

  1. palettegen 生成专用调色板。
  2. paletteuse 使用调色板编码 GIF。

相比直接执行简单的 ffmpeg input.mp4 output.gif，颜色质量通常更好。

19. Fish 配置优化

19.1 非交互保护

环境变量和 PATH 在文件前半部分设置，随后使用：

status is-interactive; or exit

这样：

  • fish -c 'command' 不会加载交互式提示符和快捷键。
  • 脚本调用 Fish 时开销更低。
  • 不会在非交互环境中启动 Atuin、Starship、fzf 等界面组件。

19.2 编辑器变量

配置不再无条件覆盖用户传入的编辑器：

set -q EDITOR; or set -gx EDITOR nvim
set -q VISUAL; or set -gx VISUAL $EDITOR

因此可以临时使用：

EDITOR=vim fish
VISUAL=code EDITOR=nvim fish

19.3 PATH

通过 fish_add_path 添加：

~/.local/bin
~/.cargo/bin
~/.local/share/pnpm/bin

相较于直接字符串拼接 $PATH，fish_add_path 能减少重复项，并遵循 Fish 的路径处理方式。

19.4 Java 与 Android

配置设置：

JAVA_HOME=/usr/lib/jvm/java-21-openjdk
ANDROID_HOME=/opt/android-sdk

如果 Android NDK 目录存在，会按版本号排序并自动选择最新版本设置 NDK_HOME。

19.5 初始化顺序

交互式工具按以下顺序初始化：

  1. CachyOS Fish 默认配置。
  2. Atuin。
  3. Zoxide。
  4. direnv。
  5. pay-respects。
  6. fzf。
  7. Starship。
  8. 自定义 Fish 快捷键。

这样可以让发行版默认配置先加载，再应用个人工具和快捷键。

Atuin 初始化时禁用它自己的：

Ctrl-R
Up Arrow
AI

避免它覆盖 Fish/fzf 的 Ctrl-R 和方向键行为。

19.6 fzf 默认扫描

存在 fd 时，文件搜索默认排除：

.git
node_modules
.cache
target
build
dist
.next
__pycache__

目录搜索最大深度为 10，并排除常见重型目录。

这样可以减少：

  • 大型依赖目录造成的延迟。
  • .git 对象进入结果。
  • Rust、Node.js 和前端构建产物淹没有效文件。
  • 缓存目录中的无关文件。

19.7 分页与手册

tarnow tar -acf

危险的自动删除 Pacman 锁文件缩写没有保留。Pacman 锁文件应先确认没有包管理进程运行，再人工处理。

21. Fish 辅助函数

21.1 mkcd

创建目录并进入：

mkcd project/src

等价于：

mkdir -p project/src
cd project/src

只接受一个目录参数，避免参数拆分造成意外行为。

21.2 cleanup

清理 Pacman 孤立包：

cleanup

函数先执行：

pacman -Qtdq

如果没有孤立包，只输出“没有孤立软件包”，不会调用空的 pacman -Rns。

有孤立包时才执行：

sudo pacman -Rns -- <包列表>

21.3 yy

启动 Yazi，并在退出后进入 Yazi 最终所在目录：

yy
yy ~/Downloads

函数使用临时 cwd 文件传递目录，并在结束后清理临时文件。

23. 常用工作流

23.1 浏览照片和视频

cd ~/Pictures
fzf-media

在界面中：

  1. 输入文件名筛选。
  2. 查看右侧封面。
  3. Tab 多选。
  4. Enter 用默认程序打开。

23.2 给一张照片添加中文水印

fzf-add-watermark \
  --text '旅行 2026' \
  --position bottom-right \
  --style border \
  --opacity 0.8 \
  photo.jpg

23.3 给整个目录的照片批量加水印

for file in *.jpg; do
  fzf-add-watermark \
    -y \
    --text 'Copyright 2026' \
    --position bottom-right \
    --style border \
    --opacity 0.7 \
    --no-preview \
    "$file"
done

建议先单独处理一张图片，确认字号、位置和透明度后再批量执行。

23.4 查找文件并交给命令

输入：

ffprobe

按 Ctrl-T 选择文件，再按 Enter 执行。

23.5 浏览 Git 变更

cd ~/code/project
fzf-git files

选择多个变更文件，用编辑器一次打开。

23.6 统一视频后再拼接

先把片段转成相同格式：

fzf-convert-media part1.mov mp4
fzf-convert-media part2.mkv mp4

再拼接：

fzf-concat-video part1.mp4 part2.mp4

实际使用时应确保输出文件名没有覆盖输入，并确认两段视频的编码参数一致。

23.7 检查下载的媒体

fzf-validate-media *.mp4

严格逐帧检查：

ffmpeg -v error -i suspect.mp4 -f null -

24. 故障排查

24.1 部署后仍然使用旧脚本

检查：

type -a fzf-preview
type -a fzf-add-watermark
type -a fzf-fftools

如果第一个路径不是 ~/.local/bin：

fish_add_path --global --prepend ~/.local/bin
exec fish

还可以刷新 Fish 命令缓存：

functions -e fzf-cd
exec fish

注意：fzf-cd 在 Fish 中应该同时存在函数和外部命令，这是正常设计。

24.2 图片仍然堆叠

先确认新版预览器：

rg -- '--format symbols' ~/.local/bin/fzf-preview-video

应该能看到：

chafa --format symbols

然后清理旧缓存并重启终端：

rm -rf ~/.cache/fzf-media-preview
reset
exec fish

如果某个单独脚本仍然直接调用 kitty +kitten icat、chafa --format kitty、viu 或其他位图协议工具，应把它的预览改为：

fzf-preview {}

24.3 没有图片预览

检查依赖：

command -v chafa
command -v file
command -v ffmpeg
command -v ffprobe

手动测试：

chafa --format symbols --size 80x24 photo.jpg
fzf-preview photo.jpg

如果只有文件信息，没有字符图片，通常是 Chafa 或输入格式解码支持问题。

24.4 视频没有封面

检查：

command -v ffmpegthumbnailer
ffprobe -v error -show_entries format=duration -of csv=p=0 video.mp4

删除对应缓存后重试：

rm -rf ~/.cache/fzf-media-preview
fzf-preview video.mp4

24.5 音频没有封面

没有内嵌封面的音频会显示波形，这是正常行为。

确认 FFmpeg 能读取音频：

ffprobe -v error -show_entries stream=codec_type -of csv=p=0 song.flac

24.6 中文水印乱码或方框

检查中文字体：

fc-match 'Noto Sans CJK SC'

安装 Noto CJK 字体后刷新缓存：

fc-cache -fv

或者使用 --font 指定字体文件。

24.7 drawtext 不可用

检查 FFmpeg：

ffmpeg -hide_banner -filters | rg drawtext

如果没有 drawtext，当前 FFmpeg 构建缺少文字渲染支持。图片 Logo 水印通常仍可使用，但文字水印需要安装带 FreeType/Harfbuzz 支持的 FFmpeg。

24.8 Ctrl-R 或 Alt 快捷键不生效

检查绑定：

bind | rg '_fzf|fzf'

重新加载：

source ~/.config/fish/config.fish

如果终端抢占 Alt 键，使用：

fish_key_reader

检查实际键序列。

24.9 fzf-cd 只打印路径，没有跳转

在 Bash 中运行外部 fzf-cd 只会输出路径，这是预期行为。

Fish 中检查函数：

functions fzf-cd

如果函数不存在：

source ~/.config/fish/functions/fzf-cd.fish

Bash 中可以使用：

cd "$(fzf-cd)"

24.10 Ctrl-Y 没有复制媒体路径

检查：

command -v wl-copy
echo test | wl-copy

fzf-media 当前优先支持 Wayland 的 wl-copy。没有该命令时会把选中路径输出到终端。

24.11 NVENC 预设失败

检查编码器：

ffmpeg -hide_banner -encoders | rg nvenc

检查 NVIDIA：

nvidia-smi

如果硬件或 FFmpeg 不支持 NVENC，请使用 x264_推荐、x265_推荐 或软件编码器。

24.12 部分媒体脚本找不到子目录文件

fzf-media、统一预览库和部分新选择器使用 fd 递归搜索。

一些保留的单用途脚本仍然只扫描当前目录第一层，例如：

  • fzf-burn-subs
  • fzf-compress-video
  • fzf-concat-video
  • fzf-extract-audio
  • fzf-mute-video
  • fzf-speed-video
  • fzf-trim-video
  • fzf-video-to-gif

使用前先进入媒体所在目录：

cd ~/Videos/project
fzf-trim-video

也可以直接把文件路径作为参数传入支持参数的脚本。

25. 已完成的优化汇总

25.1 预览层

  • 新增统一的文件、目录和媒体预览入口。
  • 图片使用 chafa --format symbols，解决终端图形协议残留。
  • 预览窗口默认 nowrap，减少刷新错位。
  • 增加 Alt-P 显示/隐藏预览。
  • 增加 Alt-W 动态切换换行。
  • 视频缩略图按路径、大小和修改时间缓存。
  • 音频优先显示封面，没有封面时生成波形。
  • 文本使用 bat 高亮，并限制预览行数。
  • 目录使用 eza 展示两层树。
  • 图片和媒体预览会根据 fzf 窗口自动限制尺寸。

25.2 水印层

  • 支持普通静态照片。
  • 支持视频、GIF 和 APNG 等动态媒体。
  • 支持文字水印和图片 Logo 水印。
  • 支持九宫格位置。
  • 支持边距和透明度。
  • 支持字号、颜色、自定义字体。
  • 支持底框、阴影、描边和纯文字样式。
  • Logo 按画面宽度百分比缩放。
  • 根据输出格式选择合理编码器。
  • 保留原始元数据。
  • 视频尽量保留原音频。
  • MP4/MOV/M4V 使用 faststart。
  • 完成后直接使用统一预览器展示结果。
  • 支持 -y 和 --no-preview，便于批处理。
  • 输出文件不能等于输入文件，保护原始素材。

25.3 fzf 工具层

  • 新增 fzf-media 统一媒体浏览器。
  • 新增 fzf-kill 安全进程终止器。
  • fzf-cd 增加 Fish 函数，能够真正改变当前目录。
  • fzf-ed 支持多选和统一预览。
  • fzf-git 增加分支、提交、文件、diff、stash 五类操作。
  • fzf-history 使用 Atuin 数据并只输出选择结果。
  • fzf-fftools 增加媒体转换、验证、水印和媒体浏览入口。
  • 媒体选择器统一使用封面预览。
  • 常见重型目录被默认排除。
  • Fish 命令补全覆盖主要脚本和参数。

25.4 Fish 配置层

  • 增加非交互模式保护。
  • 不再无条件覆盖外部 EDITOR 和 VISUAL。
  • 使用 fish_add_path 管理 PATH。
  • 自动选择最新 Android NDK。
  • 调整 CachyOS、Atuin、Zoxide、direnv、fzf 和 Starship 初始化顺序。
  • Atuin 不再抢占 Ctrl-R 和方向键。
  • Ctrl-R 选中后只插入，不自动执行。
  • 增加 Alt-E、Alt-V、Alt-G、Alt-R。
  • Git 缩写使用 switch、pull --rebase 和 force-with-lease。
  • 移除危险的 git reset --hard 和自动删除 Pacman 锁文件缩写。
  • cleanup 在没有孤立包时安全退出。
  • mkcd 验证参数数量。
  • yy 正确清理临时文件。
  • 可选工具只在命令存在时初始化或创建缩写。

26. 已知限制

  1. fzf-speed-video 的 3.0x 音频目前没有使用多段 atempo，可能与视频不同步。
  2. fzf-concat-video 使用流复制，输入编码参数不一致时会失败或产生异常输出。
  3. fzf-trim-video 使用关键帧无损裁剪，不是逐帧精确。
  4. 一部分旧单用途媒体脚本只扫描当前目录，不递归子目录。
  5. fzf-pkg 使用 Arch/CachyOS、yay 和 Omarchy 辅助命令，不是跨发行版工具。
  6. fzf-media 的剪贴板写入目前针对 Wayland 的 wl-copy。
  7. HDR/SDR 转换结果依赖源视频元数据、FFmpeg 构建和显示设备。
  8. NVENC 预设依赖受支持的 NVIDIA 显卡、驱动和 FFmpeg 编码器。
  9. 媒体完整性验证默认只检查可识别的流，不做完整逐帧解码。

for i in $(seq 1 10); do
  /usr/bin/time -f '%e' fish -i -c exit
done

本次暂存版本的本地测试启动时间约为 0.05s，实际结果会受到 Starship、Atuin、direnv、磁盘缓存和当前目录 Git 状态影响。

28. 日常使用建议

  1. 浏览媒体优先用 fzf-media 或 Alt-V。
  2. 处理媒体优先从 fzf-fftools 进入，减少记忆命令数量。
  3. 临时处理单个文件时直接给脚本传入路径，速度更快。
  4. 批处理前先用一个小文件验证参数。
  5. 原素材和输出文件放在不同目录，尤其是批量水印和转码。
  6. 拼接前先验证编码参数是否一致。
  7. 重要视频转码后使用 fzf-validate-media，必要时再做逐帧检查。
  8. 历史搜索选中命令后先检查，再按 Enter 执行。
  9. 进程终止先使用默认 TERM，不要直接使用 KILL。
  10. 图片预览异常时优先检查 chafa --format symbols 和缓存目录。
